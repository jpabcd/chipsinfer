# 产品配置说明

本目录中的 JSON 是**产品级配置**。每新增一种产品时，建议复制一个最接近的现有配置，例如 [48AMA.json](48AMA.json)，重命名后再按本文修改。

产品配置由产线入口读取，传入矩形检测、机械坐标对齐、RAW 图像读取和 Wafer Map 绘制流程。配置中出现未支持的字段会直接报错，避免拼写错误被静默忽略。

## 1. 新产品配置流程

1. 复制 `48AMA.json`，例如为新产品建立 `NEW_PRODUCT.json`。
2. 修改 `name` 和 `yolo_config`。
3. 根据一张 RAW 文件的实际规格设置 `raw_image`。
4. 使用正常样品调整 `rect_detection`，目标是每颗芯片恰好得到一个矩形框。
5. 根据检测框中心点和同一产品的机械 TXT，设置 `alignment` 中的四个间距参数。
6. 调试时先使用 `strict_align: false`；确认稳定后，量产建议改为 `true`。
7. 用正常、暗图、边缘芯片、漏检和错检样本进行回归验证。

> 注意：JSON 不支持注释。请不要在产品配置文件中加入 `//` 或 `#` 说明文字。

## 2. 完整配置模板

```json
{
  "name": "NEW_PRODUCT",
  "yolo_config": "combined_yolo_inferers_config.example.json",
  "raw_image": {
    "width": 5120,
    "height": 5120,
    "dtype": "auto",
    "byte_order": "little"
  },
  "rect_detection": {
    "x_scale": 0.3,
    "y_scale": 0.5,
    "threshold": 18,
    "x_dilate": 45,
    "y_dilate": 14,
    "min_width": 600,
    "max_width": 950,
    "min_height": 90,
    "max_height": 220,
    "min_aspect": 3.6,
    "max_aspect": 8.5,
    "min_area": 2500,
    "margin": 100
  },
  "alignment": {
    "mech_delta_x": 1421.0,
    "mech_delta_y": 283.0,
    "delta_x_pixel": 950.0,
    "delta_y_pixel": 185.0,
    "strict_align": true,
    "allow_x_reverse": false,
    "allow_y_reverse": false
  },
  "wafer_map": {
    "figsize": [20.0, 16.0],
    "chip_aspect": 5.0
  }
}
```

## 3. 顶层字段

| 字段 | 类型 | 是否建议填写 | 含义与修改方法 |
| --- | --- | --- | --- |
| `name` | 字符串 | 是 | 产品名称，仅用于识别和记录。填写产品型号，例如 `WFAW40UN`。 |
| `yolo_config` | 字符串 | 是 | 四路光源 YOLO 配置的路径，相对于工程根目录。产品使用不同模型时应修改。 |
| `raw_image` | 对象 | 是 | 无头 RAW 图像的尺寸、像素类型和字节序。相机或采集格式变化时必须检查。 |
| `rect_detection` | 对象 | 是 | 芯片矩形检测的图像处理和尺寸筛选参数。新产品最需要调试的部分。 |
| `alignment` | 对象 | 是 | 检测到的矩形框与机械 TXT 中 `MX`、`MY` 记录的配对规则。 |
| `wafer_map` | 对象 | 推荐 | 缺陷 Wafer Map 图片的显示比例；不影响检测及 OK/NG 判定。 |

## 4. `raw_image`：RAW 图像规格

| 字段 | 类型/可选值 | 含义 |
| --- | --- | --- |
| `width` | 正整数 | 单张 RAW 图像宽度，单位为像素。 |
| `height` | 正整数 | 单张 RAW 图像高度，单位为像素。 |
| `dtype` | `auto`、`uint8`、`uint16` | 原始像素类型。`auto` 根据文件大小判断 8 位或 16 位。 |
| `byte_order` | `little`、`big` | 16 位 RAW 的字节序。`uint8` 时无实际影响，建议仍保留 `little`。 |

RAW 文件没有文件头，文件大小必须符合下式：

- `uint8`：`width × height` 字节。
- `uint16`：`width × height × 2` 字节。

例如 5120 × 5120 图像的预期大小为：

| 类型 | 预期大小 |
| --- | ---: |
| `uint8` | 26,214,400 字节 |
| `uint16` | 52,428,800 字节 |

### 案例：4096 × 3000 的 16 位小端 RAW

```json
"raw_image": {
  "width": 4096,
  "height": 3000,
  "dtype": "uint16",
  "byte_order": "little"
}
```

程序会将 16 位图转换为 8 位灰度图后进行矩形检测。因此当新相机的亮度范围不同，通常还要重新调整 `threshold`。

## 5. `rect_detection`：芯片矩形检测

### 5.1 检测流程

程序按以下顺序处理用于定位芯片的图像：

1. 按 `x_scale`、`y_scale` 缩小图像；
2. 对灰度图做阈值分割，灰度值大于 `threshold` 的像素作为前景；
3. 用 `x_dilate`、`y_dilate` 对前景做矩形膨胀，使同一芯片内部断裂的亮区连接起来；
4. 查找连通域；
5. 按宽、高、宽高比和面积筛选候选框；
6. 将检测框坐标恢复到原始图像尺寸。

配置中的 `min_width`、`max_width`、`min_height`、`max_height` 均应按**原图像素尺寸**理解。内部会按缩放比例换算后再筛选。

### 5.2 参数说明

| 字段 | 含义 | 调大后的效果 | 调小后的效果 |
| --- | --- | --- | --- |
| `x_scale` | 检测图像在水平方向的缩放比例，必须大于 0。 | 保留更多横向细节，但速度更慢、内存更多。 | 更快，但窄小特征可能丢失。 |
| `y_scale` | 检测图像在垂直方向的缩放比例，必须大于 0。 | 保留更多纵向细节，但速度更慢。 | 更快，但短小特征可能丢失。 |
| `threshold` | 灰度二值化阈值。灰度值大于该值的像素被当作芯片候选区域。 | 排除暗背景和噪声，但暗芯片可能漏检。 | 更容易找回暗芯片，也更容易引入背景噪声。 |
| `x_dilate` | 水平方向膨胀半径。 | 更易连接同芯片的水平断裂区，也更易使左右芯片粘连。 | 减少左右粘连，但同一芯片可能被拆成多个框。 |
| `y_dilate` | 垂直方向膨胀半径。 | 更易连接纵向断裂区，也更易使上下芯片粘连。 | 减少上下粘连，但芯片可能上下分裂。 |
| `min_width` | 正常芯片允许的最小宽度，单位为原图像素。 | 过滤更多小噪声，但可能漏掉窄芯片。 | 接受更多候选框。 |
| `max_width` | 正常芯片允许的最大宽度，单位为原图像素。 | 容忍更宽芯片，也可能保留横向粘连大框。 | 更易过滤粘连大框，但正常宽芯片可能漏检。 |
| `min_height` | 正常芯片允许的最小高度，单位为原图像素。 | 过滤更多细小噪声。 | 允许更多矮小候选。 |
| `max_height` | 正常芯片允许的最大高度，单位为原图像素。 | 容忍更高芯片，也可能保留上下粘连大框。 | 更易过滤上下粘连。 |
| `min_aspect` | 最小宽高比，即宽除以高。 | 仅接受更扁长的芯片。 | 接受更多接近方形的目标。 |
| `max_aspect` | 最大宽高比，即宽除以高。 | 接受更细长的目标。 | 更易过滤细长条纹噪声。 |
| `min_area` | 缩放、阈值和膨胀后的连通域最小面积。 | 更强地过滤小噪声，也可能漏掉弱亮芯片。 | 保留更多弱目标和噪声。 |
| `margin` | 在整图前景外扩的检测边缘，单位为原图像素。 | 对前景边缘芯片更宽容。 | 处理区域更小，边缘芯片可能被截断。 |

### 5.3 48AMA 参数含义

当前 [48AMA.json](48AMA.json) 的芯片候选条件为：

- 宽度：600 至 950 像素；
- 高度：90 至 220 像素；
- 宽高比：3.6 至 8.5；
- 最小连通域面积：2500；
- 典型显示比例约为 5:1。

这表示该产品的芯片在图像中明显“横向长、纵向短”。近方形或竖直长条芯片不能直接沿用这些尺寸和比例范围。

### 5.4 常见调参案例

#### 案例 A：一颗芯片被识别成多个框

**现象：** 检测框数量大于机械 TXT 记录数；一颗芯片内部有断裂亮区。

**建议顺序：**

1. 先将 `x_dilate` 从 45 增加到 50 或 55；
2. 若断裂主要在上下方向，将 `y_dilate` 从 14 增加到 16 或 18；
3. 若芯片亮度不足，将 `threshold` 从 18 降到 15；
4. 每次只改一到两个参数，用同一组样本比较结果。

不要一次大幅增大膨胀参数，否则相邻芯片容易被合并。

#### 案例 B：两颗芯片粘连为一个大框

**现象：** 检测框数量小于机械 TXT 记录数；检测框宽或高明显异常。

**建议：**

```json
"rect_detection": {
  "threshold": 22,
  "x_dilate": 35,
  "y_dilate": 12,
  "max_width": 900,
  "max_height": 210
}
```

含义：提高阈值以去除连接处的暗背景，降低膨胀以减少连接，并收紧最大尺寸以排除残留的大粘连框。

#### 案例 C：背景亮点被误识别为芯片

**建议：** 提高 `threshold` 或 `min_area`，并收紧最小尺寸条件。

```json
"rect_detection": {
  "threshold": 25,
  "min_width": 650,
  "min_height": 100,
  "min_area": 4000
}
```

#### 案例 D：新产品芯片约为 1100 × 260 像素

建议从至少 20 张正常样品统计宽、高和宽高比，以正常范围为基础额外预留约 10% 至 20%。例如：

```json
"rect_detection": {
  "min_width": 950,
  "max_width": 1250,
  "min_height": 210,
  "max_height": 320,
  "min_aspect": 3.5,
  "max_aspect": 6.0
}
```

## 6. `alignment`：机械坐标对齐

机械 TXT 中需要有以 `MX MY` 开头的表头，并包含每颗芯片的一条机械记录。程序使用图像中矩形中心点的相对排布，与机械坐标中 `MX`、`MY` 的相对排布进行匹配；不依赖绝对原点相同。

| 字段 | 含义 | 何时修改 |
| --- | --- | --- |
| `mech_delta_x` | 机械坐标中相邻列的典型 `MX` 间距，通常单位为微米。必须为正数。 | 产品横向节距变化时。 |
| `mech_delta_y` | 机械坐标中同列相邻芯片的典型 `MY` 间距。必须为正数。 | 产品纵向节距变化时。 |
| `delta_x_pixel` | 图像中相邻芯片列中心的典型横向距离，单位为像素。必须为正数。 | 相机分辨率、视野或产品横向节距变化时。 |
| `delta_y_pixel` | 图像中同列相邻芯片中心的典型纵向距离，单位为像素。必须为正数。 | 相机分辨率、视野或产品纵向节距变化时。 |
| `strict_align` | 是否要求检测框数和机械 TXT 记录数完全一致。 | 调试时可关闭；稳定量产建议开启。 |
| `allow_x_reverse` | 是否允许机械 `MX` 增长方向与图像从左到右方向相反。 | 相机左右方向与机械坐标方向相反时。 |
| `allow_y_reverse` | 是否允许机械 `MY` 增长方向与图像从上到下方向相反。 | 相机上下方向与机械坐标方向相反时。 |

### 6.1 间距测量方法

对多个相邻芯片取中位数，而非只量一对，以降低偶然误差：

- `delta_x_pixel`：相邻列芯片中心点 X 坐标差的中位数；
- `delta_y_pixel`：同列相邻芯片中心点 Y 坐标差的中位数；
- `mech_delta_x`：相邻列机械记录 `MX` 差值的中位数；
- `mech_delta_y`：同列机械记录 `MY` 差值的中位数。

### 6.2 案例：新产品节距改变

实测图像横向间距为 1200 像素、纵向间距为 240 像素；机械横向间距为 1600、纵向间距为 320：

```json
"alignment": {
  "mech_delta_x": 1600.0,
  "mech_delta_y": 320.0,
  "delta_x_pixel": 1200.0,
  "delta_y_pixel": 240.0,
  "strict_align": true,
  "allow_x_reverse": false,
  "allow_y_reverse": false
}
```

### 6.3 案例：机械 MX 方向与图像左右方向相反

不要填写负数间距。保持四个间距均为正数，并开启方向反转：

```json
"allow_x_reverse": true
```

### 6.4 `strict_align` 推荐用法

- **调参期：** 使用 `false`。允许部分匹配，以便查看检测遗漏或多检的芯片位置。
- **量产期：** 使用 `true`。检测框数和机械记录数不一致时立即失败，避免静默错配。

## 7. `yolo_config`：四路模型配置

`yolo_config` 指向工程根目录中的另一份 JSON，用来配置 `light_1` 至 `light_4` 的模型权重、YOLO 推理阈值、裁剪大小以及类别过滤规则。

新产品至少确认以下内容：

1. 配置中包含四个光源：`light_1`、`light_2`、`light_3`、`light_4`；
2. 每一路 `weight` 指向存在且适用于新产品的模型权重；
3. YOLO 中的 `crop_width`、`crop_height` 能覆盖完整芯片；
4. `analyse` 中的类别名称与模型类别名称完全一致；
5. `conf` 阈值经过新产品样本验证。

> 矩形检测正确不代表 YOLO 输入正确。若芯片变宽或变高，还应同步检查 YOLO 配置中的裁剪尺寸，避免输入图截断芯片。

## 8. `wafer_map`：Wafer Map 显示参数

| 字段 | 含义 |
| --- | --- |
| `figsize` | 输出 PNG 画布尺寸，格式必须是 `[宽, 高]`，单位为英寸，两个数都必须大于 0。 |
| `chip_aspect` | Wafer Map 中单颗芯片的显示宽高比，即宽除以高。仅改变图片显示比例，不影响检测与模型判定。 |

Wafer Map 需要外部坐标 CSV 中存在可用的 `X`、`Y` 坐标后才能绘制。

### 案例：芯片宽度约为高度的 4 倍

```json
"wafer_map": {
  "figsize": [18.0, 14.0],
  "chip_aspect": 4.0
}
```

## 9. 上线前检查清单

- [ ] JSON 格式正确：字段名和字符串均使用双引号，最后一个字段后没有多余逗号。
- [ ] `name` 已改为新产品型号。
- [ ] `yolo_config` 路径存在，四路模型权重均存在。
- [ ] RAW 文件大小与 `width`、`height`、`dtype` 相符。
- [ ] 正常样品中，检测框数量与机械 TXT 记录数量一致。
- [ ] 每个芯片只对应一个框，未出现明显分裂或粘连。
- [ ] 对齐结果无异常方向，必要时开启 `allow_x_reverse` 或 `allow_y_reverse`。
- [ ] 正常、NG、暗图和边缘芯片样本均完成验证。
- [ ] 稳定量产配置已设置 `strict_align: true`。
